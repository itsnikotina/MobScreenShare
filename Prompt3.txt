Quero começar o desenvolvimento de um sistema privado de screen sharing integrado ao Discord.

Antes de implementar qualquer coisa, leia todo este prompt e pense na arquitetura.

## Objetivo

O sistema terá três partes principais:

```text
Windows/Linux App
       │
       │ mídia
       ▼
   Media Relay
       │
       │ mídia
       ▼
Discord Activity
```

A Discord Activity será hospedada no GitHub Pages.

O aplicativo desktop será responsável por transmitir a tela e o áudio.

A Activity será responsável por visualizar os streams.

O Media Relay será responsável apenas por transportar a mídia.

O Discord Bot será adicionado posteriormente para identidade, salas, autorização e sinalização.

---

# REGRA MAIS IMPORTANTE: MULTIPLATAFORMA DESDE O INÍCIO

O primeiro sistema operacional suportado será Windows.

Porém, a arquitetura deve ser criada desde o primeiro commit pensando em um futuro port para Linux.

NÃO quero construir um aplicativo Windows gigante e depois tentar adaptá-lo para Linux.

Quero:

```text
                 ┌─────────────────────┐
                 │     STREAM CORE      │
                 │        Rust         │
                 │                     │
                 │ protocol            │
                 │ transport           │
                 │ streaming           │
                 │ room                │
                 │ encoder abstraction │
                 │ audio processing    │
                 │ video processing    │
                 │ configuration       │
                 │ diagnostics         │
                 └──────────┬──────────┘
                            │
                ┌───────────┴───────────┐
                │                       │
        ┌───────▼────────┐     ┌────────▼───────┐
        │ Windows Backend │     │  Linux Backend │
        │                 │     │                │
        │ WGC             │     │ PipeWire       │
        │ WASAPI          │     │ Wayland/X11    │
        │ D3D11           │     │ DMA-BUF        │
        │ Windows codecs  │     │ Linux codecs   │
        └─────────────────┘     └────────────────┘
```

O core NÃO pode depender diretamente de:

* Windows Graphics Capture;
* WASAPI;
* D3D11;
* Media Foundation;
* APIs Win32 específicas.

Essas coisas devem ficar isoladas em implementações específicas da plataforma.

Por exemplo:

```rust
trait VideoCapture {
    ...
}
```

Windows:

```text
WindowsCapture
    └── Windows Graphics Capture
```

Futuro Linux:

```text
LinuxCapture
    └── PipeWire / Wayland / X11
```

O core só deve trabalhar com uma representação abstrata de `VideoFrame`.

Faça abstrações somente onde realmente haverá diferença entre plataformas.

Não crie dezenas de interfaces desnecessárias apenas por "boas práticas".

# ENCODER

O encoder também deve ser uma abstração.

Algo conceitualmente como:

```rust
trait VideoEncoder {
    ...
}
```

O core não deve assumir que existe NVENC, AMF, QSV ou Media Foundation.

Queremos poder ter futuramente:

```text
Windows:
    NVIDIA → NVENC
    AMD    → AMF
    Intel  → QSV
    fallback → software

Linux:
    NVIDIA → NVENC
    AMD    → VAAPI
    Intel  → VAAPI
    fallback → software
```

Não implemente todos agora.

No POC, use o método mais simples possível para gerar/enviar um stream de teste.

# MEDIA RELAY

Crie um relay mínimo.

Responsabilidades:

* aceitar conexão do streamer;
* aceitar conexão do viewer;
* associar conexões a uma sala/stream;
* encaminhar bytes binários;
* não decodificar;
* não transcodificar;
* não armazenar mídia.

Para o POC podemos usar:

```text
room_id = test-room
stream_id = test-stream
```

Não precisamos de:

* banco;
* JWT;
* Discord OAuth;
* bot;
* sistema de usuários.

Mas o código deve permitir adicionar autenticação posteriormente.

---

# PROTOCOLO DE MÍDIA

Não envie vídeo como JSON.

Não use Base64.

Queremos:

```text
encoded video bytes
        ↓
binary WebSocket frame
        ↓
relay
        ↓
binary WebSocket frame
        ↓
Activity
```

Crie um protocolo binário mínimo.

Por exemplo:

```text
HEADER

version
media_type
flags
sequence
timestamp
payload
```

Onde:

```text
media_type:
0 = video
1 = audio
```

Neste POC só:

```text
video
```

Flags podem representar:

```text
KEYFRAME
CONFIG
```

Não precisa criar um protocolo gigantesco.

Documente claramente o formato.
